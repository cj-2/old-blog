Less em si em **minha concepção** é uma ferramenta bastante simples e que pode lhe ajudar a ter um rendimento
muito bom ao trabalhar com a linguagem CSS.

Seguindo um pouco a **logica** de programação é possível se criar <del>funções</del> mixins e variáveis (que em si se comportam mais como constantes já que não é possível alterálas no decorrer do código), além de se poder criar estruturas de pai e filhos **diminuindo consideravelmente** a quantidade de códigos a ser escrito pelo desenvolvedor.

## Criando variáveis

Para se criar variáveis é **extremamente** simples, é apenas se seguir a lógica:

    // Um como funciona:
    @nome-da-variaivel: valor;

    // Um exemplo:
    @cor-bg: #EEEEEE;

Também é possível se passar **strings**, por exemplo um URL:

    @base-url: ~'https://facr.github.io/blog';

    // Podendo ser chamando assim:
    background-image: url('@{base-url}/images/bg.png');

    // Outro exemplo:
    @bg: ~'background';
    @{bg}: #FFF;

Invocado pelo **@{nome-variavel}** é retornado a string que está dentro das aspas simples '' que também pode ser usada
como uma **propriedade**, por exemplo: background, color, margin...

Ou ser chamado por **@nome-variavel**, que no caso não pode ser usada como uma
propriedade e sim apenas com um parâmetro ou valor.

**OBS:** Não é possível se chamar variáveis dentro de strings.

## Criando Mixins

Para se criar um mixin é praticamente **igual** a se atribuir comandos a uma classe ou id.

    // É possível se criar 2 tipos mixins:

    // Que não esperam parâmetros:
    .primeiroMixin {
      color: #FFF;
      margin: 15px;
      background: #000;
    }

    // E que esperam algum valor:
    .segundoMixin (@cor-borda) {
      margin-top: 20px;
      border-left: 5px solid @cor-borda;
    }

    // Que podem ser invocadas assim:
    .classAleatoria {
      .primeiroMixin;
      .segundoMixin(blue);
    }

Para mixins com padrão também é possível se passar valores padrões caso não se passe nenhum parâmetro.

    .mixinPadrao(@borda: 15px){
      border-radius: @borda;
    }

## Aninhamento, Escopo e Namespaces <del>(Objetos)</del>

Como o Less **é possível** criar aninhamentos, proteger variáveis por escopo e até criar uma estrutura **parecida** com um objeto,
os chamados namespaces.

### Aninhamento (Pai e filhos)

A lógica do aninhamento é bastante parecida com utilizada no **HTML** onde o pai guarda os filhos dentro do **próprio corpo**.

    // Seguindo a lógica do HTML
    #menu {
      background: #143642;
      text-align: center;

      ul{ // 'ul' filha de '#menu'
        padding: 20px;
        margin: 0px;

        li{ // 'li' filha da 'ul' de '#menu'
          display: inline;

          a{ // 'a' filha da 'li' da 'ul' de '#menu'
            text-decoration: none;
            color: #FFF;
          }
        }
      }
    }

O lado bom dessa pratica é a facilidade de se atribuir própriedades, porém não é recomendável se aninhar mais de **3 ou 4 filhos** em um pai pois fere as **boas práticas** do próprio CSS, deixando o código compilado com a leitura "zoada".

### Escopo

O escopo quebra um pouco a regra da edição de uma variável, pois podemos alterar o valor de determinada variável e a **proteger** dentro de uma situação.

    // Se criarmos uma variável
    @text-color: yellow;

    //E a chamarmos dentro do site, alterando seu valor.
    #site{
      @text-color: orange;
      color: @text-color;
    }

    // E definirmos depois:
    #fora-do-site{
      color: @text-color;
    }

    // A cor do texto dentro de #site será orange
    // enquanto a cor de #fora-do-site será yellow.

### Namespaces (Parecido com Objetos)

Podemos criar vários **mixins** dentro de um **namespace**, a estrutura se parece com chamar parâmetros de um objeto.

    // Se criando da seguinte forma:
    #config{
      .pad{
        padding: 15px;
      }
      .c(@c-hack){
        color: @c-hack;
      }
      .bg(@bg-hack){
        background: @bg-hack;
      }
    }

    // E se chamando os mixins assim:
    #site{
      #config > .pad;
      #config > .c(#FFF);
      #config > .bg(#007);
    }

A lógica da estrutura é também muito parecida com o aninhamento, escrito praticamente da **mesma forma**.

Por enquanto é isso.

## Imports

Para se importar arquivos dentro de um principal é usado a **mesma** estrutura do import, porem ao ser compilado, diferente do @import do CSS, tudo é compilado em um só arquivo.

    // Podemos fazer o @import de duas formas
    @import 'dev.less'; // Indicando o formato.
    @import 'dev'; // Ou não indicando nada.

  **OBS:** Caso importado um arquivo **.css** será adicionado ao código compilado não o código em si do arquivo e sim um "**@import: 'exemplo.css';**".

## & e &:extend()

O & e &:extend são duas formas de **economizar código**, sendo que o **&** é dentro do Less e **&:extend()** é no CSS compilado.

### &

Ao se usar o caractere '&' indicamos que o que está por vir irá afetar o seu pai, como o **:hover** ou o **:active** por exemplo.

    // Para não ser necessário escrever um código assim:
    .link{
      color: #FFF;
    }
    .link:hover{
      color: yellow;
      text-decoration: none;
    }

    // Usamos o & e ficará assim:

    .link{
      color: #FFF;

      &:hover{
        color: yellow;
        text-decoration: none;
      }
    }

E a saída do exemplo acima usando o '&' será **exatamente** igual ao primeiro bloco de código escrito.

### &:extend()

O exetend recebe um mixin ou uma referência (id ou classe) dentro dele e ao **compilar** junta todos os códigos com &:extend(.mixin-da-vez) ou &:extend(.classe-ou-id-da-vez) em apenas **um bloco** de CSS.

    // Se eu criar um mixin .mar
    .mar{
      margin: 15px;
    }

    // E dizer que para um id:
    #header{
      &:extend(.mar);
    }

    // E depois ainda dizer para outro id:
    #menu {
      &:extend(#header);
    }

    // Ou talvez:
    #menu {
      &:extend(.mar);
    }

    // O CSS compilado será:
    .mar,
    #header,
    #menu {
      margin: 15px;
    }

**OBS:** O extend **não** funciona com mixins que recebem **parâmetros.**

## @media Query

Para facilitar a **leitura** do código o Less nos proporcionar aninhar o **@media** dentro das nossas classes ou ids.

    // Da seguinte forma:
    #exemplo{
      width: 800px;
      @media(max-width: 500px){
        width: 400px;
      }
    }

    // Com a saída:
    #exemplo {
      width: 800px;
    }
    @media (max-width: 500px) {
      #exemplo {
        width: 400px;
      }
    }

**OBS:** Não use **extends** dentro de **@media**, pois não irão funcionar.


## Operações matemáticas

O Less oferece o suporte para operações matemáticas.

    // Crio o tamanho de um bloco.
    @bloco: 800px;

    // Digo que o filho do bloco tem a 1/2 do tamanho do bloco
    .filho-bloco {
      width: @bloco / 2;
    }

    // E o CSS compilado será:
    .filho-bloco {
      width: 400px;
    }

É possível calcular também contas entre porcentagens.

 **OBS:** Não é possível se fazer contas entre **medidas** totalmente diferentes como **px** com **mm**, porém entre **mm** e **cm** em contas com + e - é possível.

 No caso de **divisões** e **multiplicações** com medidas diferentes (Ex: mm com cm) a medida do segundo número é **desconsiderada** e a conta segue normalmente.

    // Caso exista a conta:
    .bloco{
      width: 2mm / 5cm;
    }

    // O resultado será:
    .bloco {
      width: 0.4mm;
    }

Por enquanto é o *fim*.
